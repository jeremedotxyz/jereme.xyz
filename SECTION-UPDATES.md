# Section update dates

Use independent content-update dates on the homepage, directly below each section title and before its description, with the section-updated class and a semantic time element.

- Update only the section whose content changed, using the actual date in America/Los_Angeles.
- Do not bump dates for deployments, typography, layout changes, or changes elsewhere.
- Keep the displayed date and time datetime attribute synchronized.
- Radar, listening, podcasts, audiobooks, templates, and repositories have separate dates.
- Substack uses the article publication date, labeled published, not a site update date.
- Before replacing the current five songs, preserve the outgoing rotation in listening-archive.html under its original date; check for duplicates.
- Verify dates and content on the live homepage after publishing.
